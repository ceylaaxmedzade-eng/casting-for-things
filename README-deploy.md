# Casting for Things: запуск на своём домене

Сайт — это один файл `index.html`. Заявки, сцены, фото и архив хранятся в Supabase: это бесплатная база данных с входом по ссылке на почту и правилами доступа. Пока база не подключена, на сайте работает только демо-сцена.

## 1. База данных (15 минут)

1. Зарегистрируйтесь на supabase.com и создайте проект (тариф Free). Регион выберите поближе, например Frankfurt.
2. Откройте **SQL Editor → New query**, вставьте весь файл `supabase-setup.sql` и нажмите **Run**. Он создаёт таблицы, правила доступа и публичные представления. Повторный запуск данные не стирает, поэтому после обновления сайта достаточно выполнить файл ещё раз: так добавятся новые таблицы: партитуры, звуки, паспорта вещей, композиции из мастерской, пары дублей.
3. Откройте **Authentication → URL Configuration**:
   - **Site URL**: адрес вашего сайта, например `https://casting.example.org/`
   - в **Redirect URLs** добавьте тот же адрес.
4. В **Authentication → Sign In / Providers** проверьте, что вход по Email включён. Пароли не нужны: руководитель получает ссылку на почту.

## 2. Настройки в index.html

Откройте `index.html` в любом текстовом редакторе. В самом начале `<body>` есть блок `CASTING_CONFIG`:

```js
window.CASTING_CONFIG = {
  supabaseUrl: "https://xxxx.supabase.co",   // Project Settings → API → Project URL
  supabaseAnonKey: "eyJ...",                  // Project Settings → API → anon public key
  siteUrl: "https://casting.example.org/",    // адрес сайта: на него ведут QR-коды на афишах
  contactEmail: "you@example.org"             // запасной контакт для кружков
};
```

Ключ `anon` можно публиковать: он и задуман для браузера. Чужие заявки и контакты защищены правилами в базе, а не секретностью ключа. Ключ `service_role` в файл не вставляйте никогда.

## 3. Хостинг

Подойдёт любой статический хостинг с HTTPS: Netlify (перетащить файл в Netlify Drop), Cloudflare Pages или GitHub Pages. Загрузите `index.html` и привяжите свой домен в настройках хостинга.

## 4. Как подключить кружок

1. Руководитель нажимает на сайте **Connect your club** и заполняет форму.
2. Заявка появляется в Supabase: **Table Editor → club_requests**.
3. Вы добавляете его почту в таблицу **leaders** (Insert row: `email`, `club`).
4. Руководитель нажимает **Leader sign-in**, вводит ту же почту и открывает ссылку из письма. Открывать её нужно на том же устройстве. После этого у него открывается кабинет.

Каждый руководитель видит только свои сцены, заявки на них и ответы на слепые пробы. Посетители заявки не видят вообще. На сайте показываются только счётчики и те фото, у которых руководитель поставил галочку «Show the photo on the site», без имени и контакта.

## 5. Проверка перед первым кружком

Главная проверка — один полный проход на двух устройствах. Устройство А — ноутбук руководителя, устройство Б — телефон другого человека.

1. **А.** Руководитель входит, публикует сцену с одной ролью.
2. **Б.** Открывает QR-код с афиши этой роли: должна открыться именно эта роль на вашем домене. Загружает фото вещи, примеряет её на сцене и отправляет заявку.
3. **А.** Обновляет кабинет и видит фото, примерку и контакт.
4. **А.** Открывает **Try-on on stage**, при желании правит партитуру (**Edit the score**) и нажимает **Save as this role's score** — сцена сохранена.
5. **А.** Нажимает **Print rehearsal sheet → Download (PNG)**. На листе: рисунок сцены, список вещей, три карточки партитуры словами и место для заметок. Если нажать **Add a QR code to the take**, на листе появится QR на дубль.

Потом пройдите остальное:

6. Руководитель отмечает «Chosen for the show». Новая заявка на эту роль больше не отправляется, даже из формы, которую открыли раньше.
7. **Ask a friend: what did it play?** — откройте ссылку на другом телефоне. Друг смотрит дубль без названия роли, отвечает одним словом и только потом видит вещь. Сделайте вторую попытку, привяжите её к первой (поле «second attempt of») и добавьте заметку детей.
8. Создайте роль типа **Sound**. С телефона запишите или загрузите короткий звук и фото источника. В кабинете звук играет по нажатию.
9. Отметьте «Used in the show», напишите строчку благодарности и, если владелец согласен, поставьте галочку с его именем. Сделайте **Prop Passport** для вещи, затем **Finish production**: на паспорте появится бирка, а на странице постановки — **Curtain Call**.
10. Опубликуйте превращение с тегами и приложите сравнение двух дублей. Оно появится в архиве и в **Find a backup** у других ролей.
11. Откройте ссылку владельца паспорта (из окна паспорта) и проверьте **Pause new requests**.

12. Откройте **Scene Book** (в меню или три превью на главной). В любой сцене: Play the take → See how it was made → поменяйте настройки → **Replace …** своей фотографией → **Print rehearsal sheet**. Для этого раздела база не нужна: он работает и без подключения.

Демо-примеры на сайте подписаны «Demo». Реальную историю публикуйте только после того, как спектакль действительно прошёл.

## Что стоит знать

- Фото хранятся в базе в сжатом виде (примерно 50–90 КБ каждое). Для пилота и нескольких десятков постановок этого хватит. Если сайт разрастётся, фото стоит перенести в Supabase Storage.
- Бесплатный проект Supabase засыпает после долгого простоя: его нужно разбудить в панели. Встроенная отправка писем ограничена по количеству. Для пилота этого достаточно, а для широкого запуска подключите свой почтовый сервер (Authentication → SMTP).
- QR-коды рисует небольшая библиотека с cdnjs.cloudflare.com. Если она не загрузилась, на афише печатается ссылка.
- Если открыть файл без настроек или прямо в Claude, сайт сам переключится: без настроек работает только демо-сцена, а в артефакте Claude используется хранилище Claude.
- Звуки хранятся в базе (до ~300 КБ каждый). Попросите записывать 3–5 секунд.
- Печать листа репетиции открывает окно печати браузера; если оно недоступно, скачайте PNG и распечатайте файл.
